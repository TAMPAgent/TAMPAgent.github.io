TAMPAgent Agentic Belief-Space Planning for Mobile Manipulation

Anonymous Authors

October 2026

Paper soon arXiv soon Code soon BibTeX

A robot in an unmapped home has to decide what to find out and how to act, often before it has seen where things are. Vision-language agents bring the priors for this, but when they call tools directly nothing declares what makes an action correct. Belief-space task and motion planning declares it, but pays for explicit distributions over the whole house and a hand-written problem.

TAMPAgent lets the agent act as the belief-space policy while its output keeps the planner's contract: parameterized actions whose constraints tools must certify before anything moves. Beliefs stay in language until a constraint needs a value from a tool.

Method

A conversation between agent and planner

TAMPAgent runs one loop. The agent writes the problem from its current belief, the planner grounds the actions, the agent plans with a hypothesis, the planner turns the plan into constraints, and the agent solves them with tools. Only then does the robot act, observe, and start again. Below, each step is shown on the run from the video.

1Write the problem

The agent turns the instruction into a planning problem: a goal and the current value of every variable it needs. Values the robot has not observed are hypotheses written in words. Here the agent guesses that the pink object is on the black table and the bowl is on the wooden desk.

2Ground the actions

From the problem, the planner lists the actions that can apply, each with preconditions and effects over the problem's variables. The robot has not seen the pink object yet, and its first look finds nothing.

3Plan with a hypothesis

The agent uses its priors to rank where the object could be, and commits to the most likely explanation: the penguin plush hides it. Its plan moves the penguin out of the way before looking again.

4Build the constraint graph

The planner grounds the plan into a factor graph. The continuous choices of each action, such as the grasp, arm pose, path, and placement, become variables, and each action's preconditions become constraints over them. A variable shared by two actions couples them: the grasp chosen to pick the penguin must also let the robot set it down.

5Solve it with tools

The agent composes a computation graph of tool calls, segmentation, grasp generation, inverse kinematics, and motion planning, and runs it until every constraint of the first action has a value a tool has certified.

6Act, observe, and update

The planner accepts only when every constraint of the first action is certified. The robot executes that one action and observes, and the agent updates its belief. Once the penguin is set aside, the pink object is in view: what was a hypothesis is now a mask from the camera. The loop starts again from the first step.

The rest of the run

The same loop carries the task to the end. Two base motions toward the pink object fail, so the agent picks it from where the robot stands. While carrying it, the robot searches for the bowl until perception certifies its location. No placement fits from the first stance, so the agent repositions the robot, and the object goes into the bowl.

Evaluation

Results

Six simulated tasks share one instruction, serve the apple on the plate, and differ in where the apple starts and what hides or blocks it. The robot, an RB-Y1, starts facing away from the apple every time. We compare against Code as Policies (CaP), where the same agent writes code that calls the same tools without a planner, over 20 episodes per task.

Hypotheses and long-horizon dependencies

The methods are on par when the apple is in the open (T1, T2). When it is hidden or blocked (T3 to T6), TAMPAgent succeeds in 68% of episodes against 38%. A plausible but infeasible plan, such as picking the apple through the cup, fails in the planner before the robot moves, and the failed constraint names what the agent must clear first.

Safer execution

Every motion TAMPAgent executes was certified first, so it causes 10 collisions or drops over the six tasks against 26 for CaP, and none on the drawer task, where CaP collides in 7 of 20 episodes. Its failures are mostly timeouts instead, which leave the scene intact.

Fewer tokens

The planner keeps a compact record of the problem and its progress, so the agent reads and writes less: 38% fewer uncached input tokens and 59% fewer output tokens over the six tasks, including those where success is on par.

On a real robot

On a real RB-Y1 in an office lab, TAMPAgent runs three categories of tasks. In simple pick and place, the robot puts an object such as a mustard bottle in a receptacle, finding both by exploring open surfaces. With an out-of-view receptacle, the robot carries the object while it searches, and plans the placement once the receptacle is certified. With a hidden object, as in the video above, the agent hypothesizes what hides the target and moves it first. Hidden objects cost the most, 973k uncached input and 127k output tokens per episode on average, against 376k and 39k for simple pick and place.

Questions

FAQ

What does TAMPAgent guarantee?

Every constraint of an executed action was certified by a tool under the robot's current perception. The agent can still choose a poor plan, and tools can return false positives, so a certified grasp can still fail.

What are the limitations?

Skills are hand designed, though learned policies can join as tools. Cloud-hosted agents are slow: the robot is idle for more than 90 percent of an episode while the agent reasons.
